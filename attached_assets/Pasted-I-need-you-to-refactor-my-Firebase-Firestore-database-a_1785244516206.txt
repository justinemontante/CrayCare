## System Overview

This is an IoT-based smart aquaculture system for crayfish farming.

There is ONLY ONE physical hardware package in the entire system.

The hardware package consists of:

* 1 ESP32
* Temperature Sensor
* pH Sensor
* Dissolved Oxygen Sensor
* Turbidity Sensor
* Water Level Sensor
* Automatic Feeder
* Water Pump
* Aerator

All sensors and actuators are connected to the SAME ESP32.

The ESP32 authenticates using Firebase Anonymous Authentication only.

The ESP32 NEVER knows any Firebase Authentication user UID.

The ESP32 should only send sensor readings and receive hardware commands.

## Hardware Ownership

Since there is only ONE hardware package, only ONE user can own and use it at a time.

The administrator assigns the hardware to a registered user.

Store the current owner in:

hardware_system/currentOwner

Fields:

* uid
* assignedBy
* assignedAt

This document is the ONLY source of truth for who currently owns the hardware.

Do NOT use hardwareAssignments or multiple hardware IDs because there is only one ESP32.

## Sensor Flow

The ESP32 periodically reads:

* Temperature
* pH
* Dissolved Oxygen
* Turbidity
* Water Level

It writes ONLY to:

sensorIngestion/current

The ESP32 should never write directly to any user's collection.

## Cloud Function

Whenever sensorIngestion/current changes:

1. Read hardware_system/currentOwner
2. Get ownerUid
3. Copy the latest readings into:

sensorReadings/{ownerUid}

4. Save history into:

sensorReadingsHistory/{ownerUid}/{YYYY-MM-DD}/{autoId}

This means only the CURRENT OWNER receives NEW sensor readings.
