CRAYCARE PRODUCTION FIRMWARE — SERIAL COMMANDS
Firmware environment: esp32dev_main
Baud: 115200
Line ending: Newline

IMPORTANT
- This file lists commands implemented by src/main.cpp only.
- HC-SR04 ECHO must be reduced from 5V to 3.3V before GPIO33.
- Calibration values are stored in ESP32 NVS and survive reboot.

COMMAND MENU / SENSOR DISPLAY
  HELP  (aliases: help, ?)
    Shows the main command menu.

  SENSOR_ON  (alias: sensor on)
    Prints readings as sensors are sampled: temperature, turbidity, DO, and
    ultrasonic levels every 2 seconds; pH every 5 seconds.
    Sensor values are sent to Firebase on its separate 10-second send interval.
    pH/DO/turbidity use five-sample filters; after startup, allow about 25 s
    for pH and about 10-15 s for DO/turbidity filters to fill, depending on
    the time needed to complete each sensor scan.

  SENSOR_OFF  (alias: sensor off)
    Stops periodic sensor printing so commands are easy to type. This is the
    default after every boot. Sampling, Firestore uploads, buffering, feeder,
    and actuator automation continue normally.

  SENSOR_READ  (alias: sensor read)
    Takes and prints one fresh reading without enabling periodic output.

  CAL_HELP  (alias: cal help)
    Shows calibration commands in the Serial Monitor.

  CALMODE ON / CALMODE OFF
    Enter/exit focused sensor calibration. CALMODE ON disconnects Wi-Fi,
    disables Firebase reconnect, pauses routine sensor polling/cloud control,
    and blocks feeding; serial calibration commands remain available. Enter is
    refused while a feed is active. CALMODE OFF resumes sensor polling and
    reconnects Wi-Fi; calibration-period samples are excluded from history.

  CALSTREAM PH|DO|TURB [interval_ms]
    Stream one ADC input. For DO/TURB, output remains CSV: elapsed ms, sensor,
    average ADC count, ADC-pin volts, block-average min/max, raw min/max, sample
    count, block count, and stable flag. For PH, output is labeled fields:
    `rawV` is the newest 50-sample calibrated-voltage average, `FIT_V` is the
    same five-sample median used by the live pH formula, and `fitWindowAvgV` is
    the rolling stable-window average saved by phcal commands. The PH stream
    uses at least a 5000 ms interval to match the live sensor polling cadence
    and finish its 50-sample batch; DO/TURB allow 20-2000 ms. PH stability
    requires 60 s within 10 mV; DO/TURB use their sensor-specific windows. For
    all channels, stability is judged from successive filtered/block averages,
    not raw min/max alone.
    A 1 ms text stream is not supported at 115200 baud; use 20 ms for a short
    fast check or 100 ms for readable DO/TURB calibration. For PH, the stream
    automatically raises shorter intervals to the live 5-second cadence.
    Turbidity
    volts are the ESP32 ADC-pin volts after its divider.

  CALSTOP / CALSTATUS / CALSHOW
    Stop the raw stream while staying offline / show mode and stability / show
    calibration values saved in NVS.

  WIFI_HELP  (alias: wifi help)
    Shows Wi-Fi commands in the Serial Monitor.

WIFI (up to 5 networks stored in NVS "wifiprof", survives reboot)
  wifi add
    Prompt flow: Enter SSID: -> Enter PASSWORD: -> saves + restarts.
    Safe for SSIDs/passwords with spaces. Re-saving same SSID updates it.

  wifi set <SSID>|<PASS>
    One-line version. The | separates the network name and password, so SSIDs
    may contain spaces. Example: wifi set Dave Phone Hotspot|mypass123
    Saves the profile, makes it active, and restarts.

  wifilist  (alias: wifi list)
    Shows all saved slots, e.g. 0: "Home" *active / 1: "Hotspot".

  wifi use <n>
    Switch active network, e.g. wifi use 1 -> restarts and connects there.
    Boot also auto-fallbacks through all saved slots if active is down.

  wifi delete <n>  (alias: wifi del <n>)
    Deletes one slot and shifts the rest.

  wifiscan  (alias: wifi scan)
    Scans nearby networks with RSSI + OPEN/secure.

  wifistatus  (alias: wifi status)
    Shows CONNECTED/OFFLINE, IP, RSSI, current SSID + saved list.

  RESET_WIFI
    Erases ALL stored Wi-Fi networks (legacy + multi) and restarts.

FEEDER (SG90 gate on GPIO5 — the only servo, 1 g-only model)
  FEED
    Requests one manual feed, 1-200 whole grams (default 1 g). Grams =
    actuations, so 5 g = exactly 5 gate swings. The blower always warms
    up 5 s first and stays ON through dispensing. Feeding is blocked when
    required water-quality sensors are unavailable/outside safe ranges, or
    when the feed-level estimate is empty or below the requested grams.

  GATE_TEST  (alias: gate test)
    One gate actuation 0 -> open angle -> 0. Refused while a feed runs.

  GATECAL  (alias: gatecal)
    Runs 10 actuations for weighing — expect ~10 g total. If off, adjust
    with GATE_ANGLE / GATE_MS and repeat until 10 actuations = ~10 g.

  GATE_ANGLE <10-180>  (alias: gate_angle)
    Gate open angle in degrees, saved to NVS (default 90).

  GATE_MS <100-5000>  (alias: gate_ms)
    Gate hold time in ms, saved to NVS (default 800).

BLOWER (GPIO16 relay, active-LOW)
  n4on / n4off
    Manual blower control (15-minute safety timeout). A manually-started
    blower is never switched by the feed cycle.
  Auto warm-up
    Every feed (manual, cloud, scheduled, onsite button) starts with 5 s
    of blower, which stays ON through dispensing and auto-switches OFF at
    DONE — unless it was manually started.

PHYSICAL BUTTONS (to GND, INPUT_PULLUP)
  GPIO12 onsite feed: each tap = +1 g (ISR, 50 ms debounce); taps batch in
    a 1.5 s settle window, then one feed runs with the full safety path +
    blower pre-run. Ignored while a feed runs. Cap 200 g. Live count,
    progress, and blocked reasons on LCD.
    OVERRIDE: a bypassable block (unsafe water, sensor unavailable, schedule)
    opens a 10 s warning (reason + "Tap 2x to force"). Two taps force
    the locked grams (logged forced + reason); silence cancels. Hard
    blocks (tank/clock/storage/invalid dose/critical feed level) abort with no override.
  GPIO2 blower: manual ON/OFF toggle; ignored while a feed auto-holds the
    blower. 15-minute manual safety timeout.

LCD (16x2, SDA 21 / SCL 22, addr 0x27)
  Boot progress, then 4 rotating screens: Temp/pH, DO/Turb, Water/Hopper,
  next schedule. Blower state via warm-up screen + relay status; SSID via
  boot screens + wifistatus. Live feed progress with source label
  (App/Schedule/Onsite), tap counter, transient banners, BLOCKED reasons,
    and a "Feeding completed" banner. Disabled silently if no ACK (check wiring/
  address; try 0x3F).

SENSOR CALIBRATION
  Hopper level is ultrasonic (HC-SR04 TRIG 17 / ECHO 25) by default, with the
  GPIO39 analog sensor as automatic fallback. The app always receives the
    same feed_level percentage either way.

  hopperempty
    With the hopper empty, saves the current echo distance as the 0% point.

  hopperfull
    With the hopper full, saves the current echo distance as the 100% point.
    Must read shorter than the empty point or it is rejected.

  FEEDMODE <0|1>
    0 = analog GPIO39 only, 1 = ultrasonic with analog fallback (default).

  hopperheight <5-200>
    Enter the measured distance in cm from ultrasonic sensor face to hopper
    floor. This defines the empty-hopper echo/0% point.

  hopperdepth <1-empty>
    Enter floor-to-target-full-feed-surface depth in cm. Firmware derives the
    full echo point = hopperheight - hopperdepth. Run hopperheight first.

  hoppercal
    Show saved sensor-to-floor distance, derived full echo, latest echo, and
    current fill percentage.

  feedempty
    (Analog fallback) With the hopper empty, saves the GPIO39 voltage as 0%.

  feedfull
    (Analog fallback) With the hopper full, saves the GPIO39 voltage as 100%.
    The hopper reading is reported as a percentage.

  BUFSTATUS
    Offline buffer state: active backend (SD/LittleFS), per-backend counts,
    SD size/usage. SD card (SCK 18/MISO 19/MOSI 23/CS 15, FAT32) stores
    /craycare/history.jsonl when present and syncs oldest-first on
    reconnect; LittleFS is the fallback.

  phcal4
    Offline path: CALMODE ON, CALSTREAM PH, wait for stable=YES. Online path:
    keep CALMODE OFF, run raw on, and wait for pHcal=STABLE (60 s within
    10 mV). Place the probe in pH 4.01 buffer and run this command. Saves the
    stable-window average of `FIT_V` to NVS as the acidic endpoint. `FIT_V`
    is the same filtered voltage used by the live pH conversion.

    Optional override: `phcal4 force` saves the latest averaged pH voltage
    without waiting for stable=YES. Use only when you accept that noise/drift
    can make the saved point and resulting fit inaccurate.

  phcal9 [VALUE]
    Use either the CALMODE stable=YES or normal raw-mode pHcal=STABLE window.
    Place the probe in pH 9.18 buffer, then type `phcal9 9.18`. Saves the
    stable-window average of `FIT_V` and selects pH 4.01 / 9.18.

    Optional override: `phcal9 9.18 force` (or `phcal9 force` for 9.18) saves
    the latest averaged voltage without the stability check.

  phcal686
    Use either the CALMODE stable=YES or normal raw-mode pHcal=STABLE window.
    Place the probe in pH 6.86 buffer, then type this command. Saves a
    separate stable-window average of `FIT_V` and selects pH 4.01 / 6.86.

    Optional override: `phcal686 force` saves the latest averaged voltage
    without the stability check.

    Force commands still require a recent valid pH reading. In online mode,
    start `raw on` first; in offline mode, start `CALMODE ON` and `CALSTREAM PH`.
    Force skips only the stability requirement—it does not validate that the
    probe is actually in the named buffer.

    Warning: raw-mode calibration keeps Wi-Fi/Firebase online, so pH readings
    taken in buffer solution may be sent to the app/cloud. Use CALMODE ON to
    pause cloud traffic during calibration.

  phpair 9.18 | phpair 6.86
    Select which saved second point is paired with pH 4.01. Switching selects
    only; it does not overwrite either saved point. It attempts to apply the
    fit and reports if a required point is missing.

  phfit
    Fit only pH 4.01 and the selected pH 9.18 or 6.86 point, then store
    slope/intercept in NVS. It accepts distinct endpoints separated by
    at least 1 mV; below 50 mV it still saves but prints a noise-sensitivity
    warning. Verify both buffers before relying on tank readings.

  phrefit
    Backward-compatible alias for phfit; recomputes the selected two-point pH
    calibration from saved NVS points.

  doread
    In CALMODE with CALSTREAM DO selected, shows filtered voltage, estimated
    mg/L, current temperature, and whether the live voltage window is stable.

  doclear
    In CALMODE with CALSTREAM DO stable (30 s within 10 mV), calibrates at the
    documented 100% saturation reference using the stable-window voltage and
    refreshed water temperature. Prepare the probe/reference using the exact
    procedure for your DO module.

  turbclear [volts]
    In CALMODE with CALSTREAM TURB stable (10 s within 10 mV), save the
    stable-window voltage as the clear-water (0 NTU) point. Optional voltage
    must be within 10 mV of the stable-window average.

  turbdirty [volts]
    Save the stable-window voltage as the dirty-water (500 NTU field reference).
    Optional voltage must be within 10 mV of the stable-window average.

  turbair [volts]
    Save the stable-window voltage as the air/no-water threshold. Optional
    voltage must be within 10 mV of the stable-window average. Mapping is
    valid only when clear voltage > dirty voltage > air threshold; CALSHOW
    reports whether the mapping is complete and valid.

HC-SR04 WATER LEVEL
  tankheight <cm>
    Enter distance from ultrasonic sensor face to tank bottom.

  tankdepth <cm>
    Enter vertical distance from tank bottom to the target/full water surface.
    This must be less than tankheight. Firmware derives water depth as
    tankheight minus the live sensor-to-water-surface echo distance.

  tankcal
    Shows saved tank geometry, latest sensor-to-water-surface echo, and
    computed water depth. Measure both values, then confirm the sensor is
    mounted vertically above the water.

  Formula: waterDepth = sensorHeight - measuredDistance

DEBUG
  raw
    Prints pH, DO, turbidity, water depth, plus hopper voltage, percentage, and
    raw hopper distance where available.

  raw on / raw off
    Normal-mode stream of cached readings every 1 s. `FIT V` is the current
    filtered voltage used by the live pH formula; `pHcal avg` is the stable
    window of that same signal used by online pH calibration. For offline
    calibration use CALMODE + CALSTREAM PH, which now uses the same filter.

RELAYS — LOCAL TEST
  n1on / n1off       Water pump, GPIO26
  n2on / n2off       Primary aerator, GPIO27
  n3on / n3off       Secondary aerator, GPIO14
  n4on / n4off       Blower, GPIO16 (15-min manual safety timeout)
  relay status       Shows physical relay states and cloud control modes
                     (plus blower state)
  Offline behavior: pump and both aerators default to ON at boot and are
    forced ON when Wi-Fi/Firebase is unavailable. Cloud modes take over again
    after Firebase is reachable; local OFF commands do not override offline
    life-support fallback.

NOTES
- Local relay test state can be replaced by the next Firestore control sync.
- Cached schedules are restored from NVS for offline use. A cold boot without
  network still requires a valid clock (for example, an external RTC) and the
  normal feed safety/configuration checks must pass before dispensing.
- Sensor thresholds are configured in the Flutter app and synchronized from
  tanks/{tankId}/sensors/*.
- Scheduled feeding is executed by the ESP32. Cloud Functions send reminders;
  the mobile app does not enqueue duplicate scheduled feed commands.
- The latest complete cloud-synced schedules are cached in NVS and continue
  during a Wi-Fi outage. Ten-minute sensor history is buffered in LittleFS and
  uploaded after reconnect. A cold boot without network still needs an external
  RTC for correct wall-clock schedule time.
