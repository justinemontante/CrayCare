BLOWER (GPIO16, active-LOW relay module)
  - Wiring: GPIO16 -> relay IN, common GND, blower on its own supply.
    Relay module must trigger on 3.3V logic. Initializes OFF at boot.
  - Warm-up: auto-ON 5 s before EVERY feed (manual, cloud, scheduled,
    onsite button),
    stays ON through dispensing, auto-OFF at DONE — unless manually ON
    via n4on, which the feed cycle never overrides.
  - Manual: n4on / n4off (15-minute safety timeout). Future app ID
    (reserved): "blower".

FEEDER GATE — SG90 180-DEGREE SERVO ON GPIO5 (LEDC ch 0, ONLY servo)
  - 1 g-only model: 1 open/close actuation = 1 g, always. Feed grams from
    the app decide the count: 5 g = exactly 5 actuations.
  - Motion per actuation: 0 -> GATE_OPEN_ANGLE (default 90) -> hold
    GATE_HOLD_MS (default 800 ms) -> 0 -> 300 ms close dwell -> next gram.
    The dwell lets the servo physically shut (same gap as GATECAL).
    Tune on bench, store permanently.
  - Calibration: GATECAL runs 10 actuations — catch, weigh, expect ~10 g.
    Adjust GATE_ANGLE / GATE_MS until 10 actuations land near 10 g.
    Test a single swing with GATE_TEST.
  - Parks at 0 on boot and after FEEDER_DONE. Never actuates at boot.
  - GPIO25 door servo retired (spare). GPIO13 retired (dead output).
  - Power from separate 5V supply with common GND + ~470 uF cap on
    the servo rail. Never power servos from the ESP 5V pin.

HOPPER LEVEL (2nd HC-SR04, feed surface)
  - TRIG GPIO17 (direct), ECHO GPIO25 via 1kΩ (ECHO->GPIO) + 2kΩ
    (GPIO->GND) divider — never direct, same rule as GPIO33.
  - No ruler needed: empty hopper -> `hopperempty`, full hopper ->
    `hopperfull`. Percent = (empty - echo) / (empty - full).
    Manual values: `hopperheight <5-200>` (empty point),
    `hopperdepth <1-empty>` (max feed depth).
  - Source: ultrasonic by default; `FEEDMODE 0` forces analog GPIO39.
    A bad echo falls back to analog automatically; both invalid blocks
    feeding exactly like before. App sees identical feed_level/grams.

SD CARD (offline storage, syncs when internet returns)
  - SPI mode: SCK 18 / MISO 19 / MOSI 23 / CS 15. Active driver:
    SD is the primary offline buffer (/craycare/history.jsonl);
    LittleFS /buf/history.jsonl is the fallback with no card, and any
    LittleFS backlog migrates to SD at boot. Flush order SD-first.
  - Module VCC to 5V (onboard regulator), signals at 3.3V, common GND.
    Format card as FAT32. Check state any time with BUFSTATUS.
  - GPIO15 (MTDO) needs HIGH at boot — SD CS idles HIGH through its
    pull-up, so this assignment is safe.

NOTE: GPIO39 is an ADC1 input-only pin and remains usable while Wi-Fi is active.
The default analog calibration is 0.50V empty and 2.80V full. Run `feedempty`
and `feedfull` after installing the actual sensor. GPIO36 remains reserved
exclusively for the dissolved-oxygen analog input.

  VOLTAGE DIVIDER CONFIGURATION
============================================

Sensor powered at 5V — verify each before connecting:

┌──────────────┬────────────┬───────────────────────────────────┐
│ Sensor       │ Divider    │ Ratio in Code   │ Status          │
├──────────────┼────────────┼─────────────────┼─────────────────┤
│ DO (SEN0237) │ 10k + 10k  │ 0.5f            │ KEEP RESISTORS  │
│ pH (SEN0161) │ 10k + 10k  │ 0.5f            │ KEEP RESISTORS  │
│ Turbidity    │ None needed│ N/A             │ Direct connect  │
│              │ (if 3.3V)  │                 │ at 3.3V only    │
└──────────────┴────────────┴─────────────────┴─────────────────┘

⚠️  IMPORTANT: SEN0189 Turbidity at 5V outputs ~3.8-4.2V.
    If powered at 5V, add voltage divider. Direct connect only
    if powered at 3.3V.
    After adding ANY divider, reteach turbclear + turbdirty: the NTU
    scale interpolates between the taught voltages, so old taught
    values (taken undivided) become wrong the moment a divider lands.

SEPARATE 5V ADAPTER RULES (sensors, ultrasonics, servo, LCD)
  A separate adapter changes NOTHING about resistors: dividers care about
  SIGNAL voltage, not SUPPLY source. HC-SR04 ECHO still outputs ~5V, so the
  1k+2k dividers stay mandatory, as do all dividers/pull-ups below.
  - COMMON GND IS MANDATORY. Tie the adapter GND to ESP32 GND (best: star
    grounding at one point). Without it every sensor reading floats
    (garbage values) and TRIG/ECHO/servo signals have no reference.
  - DS18B20 pull-up goes to 3.3V ALWAYS, even if the sensor VCC is 5V
    (open-drain DQ: the pull-up voltage sets the logic level). A 5V
    pull-up puts 5V on GPIO4 = damaged pin.
  - TRIG pins (GPIO32/17) stay direct: 3.3V registers as HIGH on the 5V
    ultrasonic modules. Servo signal likewise stays direct (3.3V).

HOW TO CONNECT EACH RESISTOR (signal -> resistors -> ESP -> GND)
  Stock on hand: 10k, 5.1k, 1k, 2k (+ 220, 10, 100, 330, 100k, 1M).
  Use ONLY 10k / 5.1k / 1k / 2k for the circuits below. Avoid 100k/1M
  (too high: ADC leakage skews readings) and 220 and below (too low:
  loads the sensor output and wastes current).
  DO (GPIO36) and pH (GPIO35), 10k + 10k each:
    module SIG -> 10k -> GPIO pin; GPIO pin -> 10k -> GND.
    Why kept: both DFRobot modules output 0-3.0V, so the divider gives
    0-1.5V at the ADC — comfortable headroom, never clips, and safe
    against 5V-supply overshoot. Firmware compensates (/0.5), so readings
    stay correct. Removing them would need a code change AND a full
    recalibration (pH slope, DO point, all taught voltages) for ~1 mV
    of extra resolution — not worth it. Leave them alone.
  Turbidity (GPIO34, 5V supply), 10k + 10k:
    module SIG -> 10k -> GPIO34; GPIO34 -> 10k -> GND.
    Then reteach turbclear + turbdirty (see above). No code change:
    the 2:1 scale is absorbed by the taught points.
  DS18B20 temp (GPIO4), one 5.1k pull-up (ideal value, in stock):
    DQ -> 5.1k -> 3.3V; DQ -> GPIO4; VCC -> 3.3V; GND -> GND.
    REQUIRED for reliable OneWire. Symptom of a weak/missing pull-up:
    -127 C / 85 C readings or dropouts. (Backup: 10k on short wires
    < 1 m, or 2x10k in parallel = ~5k.)
  HC-SR04 ECHO (GPIO33 water, GPIO25 hopper), 1k + 2k each:
    ECHO -> 1k -> GPIO pin; GPIO pin -> 2k -> GND. Never direct.
  Buttons/SD/LCD/servo need no extra resistors (internal pull-ups /
  module-level shifting; see LCD 5V pull-up advisory in project notes).

DIVIDER CONNECTION DIAGRAMS (ASCII, signal flows left to right)
  10k + 10k divider (DO->GPIO36, pH->GPIO35, turbidity->GPIO34 @5V):

      module SIG o----[ 10k ]----+----o GPIO pin
                                  |
                             [ 10k ]
                                  |
                                 GND
      GPIO reads HALF the module voltage; firmware compensates (/0.5
      for DO/pH; turbidity absorbs it via reteach). Either 10k can be
      on either side — the ratio is what matters.

  1k + 2k divider (HC-SR04 ECHO -> GPIO33 water / GPIO25 hopper):

      ECHO (5V) o----[ 1k ]----+----o GPIO pin
                                |
                               [ 2k ]
                                |
                               GND
      GPIO sees 5V * 2k/(1k+2k) = 3.3V. Do NOT swap the values: 2k on
      top would give 1.7V (weak echo reads); direct wire gives 5V
      (damages the pin).

  DS18B20 pull-up (DQ -> GPIO4):

      3.3V o----[ 5.1k ]----+----o DQ / GPIO4
      (VCC -> 3.3V, GND -> GND; DQ doubles as the data line.)

============================================
  WATER LEVEL (HC-SR04)
============================================

Tank configuration:
  - Sensor mounted at: 65cm above tank bottom
  - Tank water depth:  23cm max
  - Water depth = 65cm − measured_distance

⚠️ HC-SR04 ECHO is normally 5V. Never connect ECHO directly to ESP32 GPIO33.
   Use a 5V→3.3V level shifter or resistor divider (for example 1kΩ from ECHO
   to GPIO33 and 2kΩ from GPIO33 to GND). TRIG may connect to GPIO32.

LCD display: boot progress, then 5 rotating screens (Temp/pH, DO/Turb,
Water/Hopper, next schedule, blower+WiFi/SSID); live feed progress with
source label, tap counter, transient banners, "Fed Xg OK". Silent-disabled
if no ACK at 0x27 — if your backpack is 0x3F, change LCD_ADDR in main.cpp.

============================================
  PHYSICAL BUTTONS (to GND, INPUT_PULLUP)
============================================

  GPIO12 = ONSITE FEED. Each tap = +1 g (ISR counted, 50 ms debounce);
  taps batch in a 1.5 s settle window, then one feed runs (3 taps = 3 g,
  single 5 s blower pre-run). Taps ignored while a feed runs. Cap 200 g.
  Full safety path: sensor/block checks + blower + gate swings. Live
  count + blocked reasons on LCD.
  OVERRIDE: a bypassable block (unsafe water, low hopper, schedule
  conflict) opens a 10 s warning instead of aborting — LCD shows the
  reason + "Tap 2x to force". Two taps inside the window force-dispense
  the locked grams (logged as forced with reason); no taps = cancelled.
  Hard blocks (tank/clock/storage/grams) never offer override.

  GPIO2 = BLOWER toggle (manual ON/OFF). Ignored while a feed auto-holds
  the blower. 15-minute manual safety timeout. Neither pin is a boot
  strapping risk with buttons to GND (pressed = LOW).

  HELP / help / ?        Show the main command menu
  SENSOR_ON              Print readings every 2 seconds
  SENSOR_OFF             Hide periodic readings (default after boot)
  SENSOR_READ            Take and print one fresh reading
  CAL_HELP               Show calibration commands
  WIFI_HELP              Show Wi-Fi commands

  n1on / n1off         Water Pump ON/OFF       (GPIO 26)
  n2on / n2off         Primary Aerator ON/OFF  (GPIO 27)
  n3on / n3off         Secondary Aerator ON/OFF(GPIO 14)
  n4on / n4off         Blower ON/OFF           (GPIO 16)
  relay status         Show relay states

FEEDER (SG90 gate on GPIO5, 1 g per actuation)
  FEED                  Request one manual feed (1-200 whole g, default 1 g)
  GATE_TEST             One gate actuation 0 -> angle -> 0
  GATECAL               10 actuations for weighing (expect ~10 g)
  GATE_ANGLE <10-180>   Gate open angle, saved to NVS
  GATE_MS <100-5000>    Gate hold ms, saved to NVS
BLOWER
  Blower auto-runs 5 s before every feed, stays ON through dispensing,
  auto-OFF at DONE unless manually ON. Manual: n4on / n4off.

WIFI (up to 5 profiles saved in NVS)
  wifi add                 Guided SSID/password entry
  wifi set <SSID>|<PASS>   Save/update profile; SSID may contain spaces
  wifi list / wifilist     List profiles; passwords stay hidden
  wifi use <INDEX>         Switch profile and restart
  wifi delete <INDEX>      Delete one profile
  wifi scan / wifiscan     Scan nearby networks
  wifi status / wifistatus Show connection and saved profiles
  RESET_WIFI               Erase every saved profile and restart

CALIBRATION
  turbclear <V>        Turbidity 0 NTU voltage
  turbdirty <V>        Turbidity ~500 NTU voltage
  turbair <V>          Turbidity air threshold
  phcal7               Calibrate pH 7.0
  phcal4               Calibrate pH 4.0
  doclear              Calibrate DO in air
  feedempty            Save current hopper voltage as empty
  feedfull             Save current hopper voltage as full

DEBUG
  raw                   Print one raw sensor reading
