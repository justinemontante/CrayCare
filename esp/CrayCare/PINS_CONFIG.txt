BLOWER (GPIO16, active-LOW relay module)
  - Wiring: GPIO16 -> relay IN, common GND, blower on its own supply.
    Relay module must trigger on 3.3V logic. Initializes OFF at boot.
  - Warm-up: auto-ON 5 s before EVERY feed (manual, cloud, scheduled,
    onsite button),
    stays ON through dispensing, auto-OFF at DONE — unless manually ON
    via n4on, which the feed cycle never overrides.
  - Manual: n4on / n4off (15-minute safety timeout). Future app ID
    (reserved): "blower".

FEEDER GATE — SG92R SERVO (latest reported signal GPIO13)
  - 1 g-only model: 1 open/close actuation = 1 g, always. Feed grams from
    the app decide the count: 5 g = exactly 5 actuations.
  - Motion per actuation: 0 -> GATE_OPEN_ANGLE (default 90) -> hold
    GATE_HOLD_MS (default 800 ms) -> 0 -> 300 ms close dwell -> next gram.
    The dwell lets the servo physically shut (same gap as GATECAL).
    Tune on bench, store permanently.
  - Calibration: GATECAL runs 10 actuations — catch, weigh, expect ~10 g.
    Adjust GATE_ANGLE / GATE_MS until 10 actuations land near 10 g.
    Test a single swing with GATE_TEST.
  - Parks at 0 on boot and after FEEDER_DONE. Never actuates at boot.
  - Wiring/code mismatch to resolve: firmware still sets GATE_SERVO_PIN to
    GPIO5; latest reported physical wiring uses GPIO13.
  - Power from separate 5V supply with common GND + ~470 uF cap on
    the servo rail. Never power servos from the ESP 5V pin.

HOPPER LEVEL (2nd HC-SR04, feed surface)
  - Firmware pin assignment: TRIG GPIO17 (direct), ECHO GPIO25 through
    the 2kΩ + 1kΩ divider. Divider order matters: ECHO -> 2kΩ -> GPIO node,
    then GPIO node -> 1kΩ -> GND gives only about 1.67V from a 5V Echo
    (1.77V at 5.3V), which may not be detected reliably as HIGH. Prefer
    ECHO -> 1kΩ -> GPIO node -> 2kΩ -> GND (about 3.33V from 5V), or use
    a 5V-to-3.3V level shifter. Confirm the physical Echo wire is on GPIO25
    and the physical TRIG wire is on GPIO17 to match this documented map.
  - No ruler needed: empty hopper -> `hopperempty`, full hopper ->
    `hopperfull`. Percent = (empty - echo) / (empty - full).
    Manual values: `hopperheight <5-200>` (empty point),
    `hopperdepth <1-empty>` (max feed depth).
  - Source: ultrasonic by default; `FEEDMODE 0` forces analog GPIO39.
    A bad echo falls back to analog automatically; both invalid blocks
    feeding exactly like before. App sees the same feed_level percentage.

SD CARD (offline storage, syncs when internet returns)
  - 6-pin module mapping (module silkscreen -> ESP pin):
      CS   -> GPIO15   (chip select)
      SCK  -> GPIO18   (clock)
      MOSI -> GPIO23   (ESP -> card, commands)
      MOSO -> GPIO19   (card -> ESP, data back; this IS the MISO line —
                        some modules print MOSO instead of MISO)
      VCC  -> 5V (onboard regulator) | GND -> GND (common with ESP)
    NEVER cross data lines: MOSI->MOSI, MOSO->MISO. (Unlike UART Tx/Rx,
    SPI module labels connect straight through.) No DAT1/DAT2 breakout
    on 6-pin modules — not needed in SPI mode.
  - Active driver: SD is the primary offline buffer (/craycare/history.jsonl);
    LittleFS /buf/history.jsonl is the fallback with no card, and any
    LittleFS backlog migrates to SD at boot. Flush order SD-first.
  - Format card as FAT32. Check state any time with BUFSTATUS.
  - GPIO15 (MTDO) needs HIGH at boot — SD CS idles HIGH through its
    pull-up, so this assignment is safe.
  - Still LittleFS after wiring + FAT32 card? Check: module seated, CS
    pull-up present, SPI wires < 20 cm, 5V reaching the module, then
    paste the BUFSTATUS output for diagnosis.

NOTE: GPIO39 is an ADC1 input-only pin and remains usable while Wi-Fi is active.
The default analog calibration is 0.50V empty and 2.80V full. Run `feedempty`
and `feedfull` after installing the actual sensor. GPIO36 remains reserved
exclusively for the dissolved-oxygen analog input.

⚠️  IMPORTANT: DFRobot SEN0189 specifies analog output up to 4.5V.
    For 5V module power, use the latest reported 2.2kΩ upper + 3.3kΩ
    lower divider (output -> 2.2k -> ADC node; ADC node -> 3.3k -> GND).
    After adding ANY divider, reteach turbclear + turbdirty: the NTU
    scale interpolates between the taught voltages, so old taught
    values (taken undivided) become wrong the moment a divider lands.

SEPARATE 5V ADAPTER RULES (sensors, ultrasonics, servo, LCD)
  A separate adapter changes NOTHING about resistors: dividers care about
  SIGNAL voltage, not SUPPLY source. HC-SR04 ECHO still outputs ~5V, so a
  divider/level shifter remains mandatory; use the orientation specified below.
  - COMMON GND IS MANDATORY. Tie the adapter GND to ESP32 GND (best: star
    grounding at one point). Without it every sensor reading floats
    (garbage values) and TRIG/ECHO/servo signals have no reference.
  - DS18B20 pull-up goes to 3.3V ALWAYS, even if the sensor VCC is 5V
    (open-drain DQ: the pull-up voltage sets the logic level). A 5V
    pull-up puts 5V on GPIO4 = damaged pin.
  - TRIG pins (GPIO32/17) stay direct: 3.3V registers as HIGH on the 5V
    ultrasonic modules. Servo signal likewise stays direct (3.3V).

HOW TO CONNECT EACH RESISTOR (signal -> resistors -> ESP -> GND)
  Resistor inventory previously reported: 10k, 5.1k, 1k, 2k (+ 220, 10,
  100, 330, 100k, 1M). Use appropriate values for each divider below.
  Avoid 100k/1M (too high: ADC leakage skews readings) and 220Ω and below (too low:
  loads the sensor output and wastes current).
  DO (GPIO36): latest reported wiring is direct A/O -> GPIO36, common GND.
    DFRobot specifies SEN0237 board supply 3.3-5.5V and output 0-3.0V;
    no divider is required by that output specification.
  pH (GPIO35): latest reported wiring is direct A/O -> GPIO35, common GND.
    DFRobot specifies 5.00V module power but its SEN0161 page does not list
    the analog-output maximum. Verify the exact V1.1 board output stays
    within ESP32 input limits. Recalibrate after any signal-path change.
  Turbidity (GPIO34, 5V supply), 2.2k + 3.3k:
    module SIG -> 2.2k -> GPIO34; GPIO34 -> 3.3k -> GND.
    Then reteach turbclear + turbdirty (see above). No code change:
    the 2:1 scale is absorbed by the taught points.
  DS18B20 module (GPIO4): the previously shared module photo shows a
    resistor marked 472 (nominal 4.7kΩ). If it is wired as a pull-up from
    DATA/DQ to VCC, use that onboard resistor and do not add another one.
    Power VCC from 3.3V, connect DATA to GPIO4 and GND to common GND.
    If the resistor is not actually between DATA and 3.3V, add one external
    4.7kΩ (or 5.1kΩ) from DATA to 3.3V. Symptom of a weak/missing pull-up:
    -127 C / 85 C readings or dropouts. (Backup: 10k on short wires
    < 1 m, or 2x10k in parallel = ~5k.)
  HC-SR04 ECHO (water/hopper), latest reported resistors are 2k and 1k.
    Higher-output order: ECHO -> 1k -> GPIO node; GPIO node ->
    2k -> GND. This gives 3.33V from 5V Echo. If instead wired ECHO ->
    2k -> GPIO node -> 1k -> GND, GPIO sees only 1.67V (1.77V at 5.3V),
    too low for guaranteed HIGH recognition. Never connect Echo directly.
  Buttons/SD/LCD/servo need no extra resistors (internal pull-ups /
  module-level shifting; see LCD 5V pull-up advisory in project notes).

DIVIDER CONNECTION DIAGRAMS (ASCII, signal flows left to right)
  2.2k + 3.3k divider (turbidity->GPIO34 @5V):

      module SIG o----[ 2.2k ]--+----o GPIO34
                                  |
                             [ 3.3k ]
                                  |
                                 GND
      The sensor's specified 4.5V maximum becomes about 2.7V at GPIO34.

  2k + 1k resistors (HC-SR04 ECHO):

      ECHO (5V) o----[ 1k ]----+----o GPIO pin (recommended order)
                                |
                               [ 2k ]
                                |
                               GND
      GPIO sees 5V * 2k/(1k+2k) = 3.33V. If 2k is upper and 1k lower,
      it sees only 1.67V and Echo may fail to read. At a 5.3V Echo the
      higher-output order yields 3.53V nominal, very near the 3.6V GPIO
      limit. With supply/resistor tolerances this has little margin; use a
      proper 5V-to-3.3V level shifter for the robust design.

  DS18B20 pull-up only if the module does not already provide it:

      3.3V o----[ 4.7k-5.1k ]+----o DQ / GPIO4
      (VCC -> 3.3V, GND -> GND; DQ doubles as the data line.)

============================================
  WATER LEVEL (HC-SR04)
============================================

Tank configuration:
  - Sensor mounted at: 65cm above tank bottom
  - Tank water depth:  23cm max
  - Water depth = 65cm − measured_distance

⚠️ HC-SR04 ECHO is 5V logic. Never connect ECHO directly to an ESP32 GPIO.
   The latest reported 2kΩ/1kΩ values only provide a useful HIGH in the
   order 1kΩ from ECHO to GPIO node and 2kΩ from node to GND. A proper
   5V-to-3.3V level shifter is more robust. Water sensor is TRIG GPIO32 /
   ECHO GPIO33. Hopper mapping needs confirmation against the installed wires.

LCD display: boot progress, then 4 rotating screens (Temp/pH, DO/Turb,
Water/Hopper, next schedule); blower state via warm-up screen + relay
status cmd; SSID via boot screens + wifistatus. Live feed progress with
source label, tap counter, transient banners, "Fed Xg OK". Silent-disabled
if no ACK at 0x27 — if your backpack is 0x3F, change LCD_ADDR in main.cpp.

============================================
  PHYSICAL BUTTONS (to GND, INPUT_PULLUP)
============================================

  GPIO12 = ONSITE FEED. Each tap = +1 g (ISR counted, 50 ms debounce);
  taps batch in a 1.5 s settle window, then one feed runs (3 taps = 3 g,
  single 5 s blower pre-run). Taps ignored while a feed runs. Cap 200 g.
  Full safety path: sensor/block checks + blower + gate swings. Live
  count + blocked reasons on LCD.
  OVERRIDE: a bypassable block (unsafe water, low hopper, schedule
  conflict) opens a 10 s warning instead of aborting — LCD shows the
  reason + "Tap 2x to force". Two taps inside the window force-dispense
  the locked grams (logged as forced with reason); no taps = cancelled.
  Hard blocks (tank/clock/storage/grams) never offer override.

  GPIO2 = BLOWER toggle (manual ON/OFF). Ignored while a feed auto-holds
  the blower. 15-minute manual safety timeout. Neither pin is a boot
  strapping risk with buttons to GND (pressed = LOW).
